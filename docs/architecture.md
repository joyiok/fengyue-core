# 架构与设计：为什么是这样

> 读者是接手这个仓库的人。README 讲**有什么**（功能、接口、怎么跑），这份讲**为什么这么做**、以及**代价是什么**——尤其是那些看起来"少做了一点"的地方，它们大多是权衡，不是遗漏。
>
> 代码是唯一真相：本文引用的文件与函数名都对应到当前实现。

---

## 0. 一句话

角色卡的生态价值在**格式**里，不在某一个实现里。所以这一层只做两件事：**把格式读干净**，**把提示词拼对**。其余（账号、额度、市场、部署）都是让这两件事能对外服务的外壳。

---

## 1. 分层与依赖方向

```
src/png/         PNG chunk 编解码 + CRC-32（无依赖）
src/cards/       卡类型归一化（V1/V2/V3）、PNG/JSON 读写
src/worldbooks/  世界书类型 + 缺省填充
src/chats/       会话 JSONL
src/prompt/      提示词引擎：纯函数（assemble / worldinfo / memory / estimate）
src/gateway/     OpenAI 兼容适配器 + 配置
src/chat/        会话：建会话、发一轮、流式、重新生成、落盘
src/db/          SQLite 打开、迁移、事务
src/auth/        密码哈希（scrypt）、账号、会话
src/billing/     额度：预留、结算、不可变用量流水
src/credits/     积分：签到、邀请、计价
src/market/      发布快照、搜索、收藏、按天聚合榜单
src/library.ts   套在"酒馆数据目录"上的文件库
src/server.ts    HTTP（node:http，无框架）
src/cli.ts       命令行
deploy/          Docker Compose 部署形态
```

依赖只朝一个方向：上层依赖下层，`prompt/` **不碰 I/O**。这条约束换来了两件事——提示词引擎可以用纯输入输出的快照测试覆盖（`test/prompt.test.ts`、`test/worldinfo.test.ts`），以及"同一份历史 + 同一份卡"永远拼出同一个提示词。

## 2. 零运行时依赖：换来了什么，代价是什么

运行时依赖为零：Node 22 自带 `node:zlib`（PNG 解压）、`node:sqlite`、`node:http`、`node:test`、`node:crypto`，Node 22 还能直接跑 TypeScript（类型擦除，无需构建步骤）。

**换来**：镜像就是 `node:22-alpine` + `src/`（239MB，没有 `npm install`、没有 node_modules）；没有供应链攻击面；没有需要跟踪的安全公告；三年后 `git clone && node src/server.ts` 仍然能跑。

**代价**（这些都是有意识接受的）：

| 代价 | 说明 |
|---|---|
| PNG/CRC-32 自己写 | `src/png/` 约 200 行，风险由交叉验证测试兜住（§3） |
| 没有 ORM | SQL 直接写在服务里；表结构变更靠版本化迁移（§9） |
| 没有 Web 框架 | 路由手写几十行；换来 SSE 路径完全可控（§8） |
| token 数只能**估算** | 没有目标模型的分词器（§4.4） |

**什么时候该放弃这条原则**：接 PostgreSQL、上 Redis、要模板引擎、要自动生成 OpenAPI。前两个是明确记录在案的扩展点，且都不会波及格式层与提示词层。

## 3. 格式层

### 3.1 三种资产

| 资产 | 格式 | 实现 |
|---|---|---|
| 角色卡 | PNG + `tEXt` chunk：关键字 `chara`(V2) / `ccv3`(V3，**读取优先**)，值为 base64 的卡片 JSON | `src/png/chunks.ts`、`src/cards/io.ts` |
| 世界书 | JSON，`entries` 是 `id → 词条`，31 个字段 | `src/worldbooks/io.ts` |
| 会话 | `<角色>/<会话>.jsonl`：首行是 header（`chat_metadata` / `user_name` / `character_name`），之后每行一条消息 | `src/chats/jsonl.ts` |

写入 PNG 时**同时写 `chara` 与 `ccv3`**，与酒馆一致：新版酒馆优先读 `ccv3`，老工具只认 `chara`。

### 3.2 归一化，而不是分支

V1（扁平）、V2（`data` 下）、V3（V2 + `assets` 等）在读入时统一归一化成 V2 结构（`src/cards/types.ts: normalizeCard`），此后所有代码都不再判断版本。残缺文件（第三方工具导出的）按缺省补全而不是报错——**导入别人的资产是这条路线的核心价值，不是边界情况**。

### 3.3 目录布局：故意的兼容

`<root>/characters/*.png`、`<root>/worlds/*.json`、`<root>/chats/<角色>/*.jsonl` 与酒馆完全一致，所以"把根目录指向酒馆的数据目录"就能直接工作，反向导出也能被酒馆读回。**搬家零成本是相对同类产品的差异化优势**，这条布局是它的前提。

### 3.4 唯一的有效验收：用对方的解析器读回来

自己写、自己读，只能证明自己自洽。所以互操作测试是：用本项目的写卡器导出一张 PNG → 放进酒馆容器 → **在容器里调用酒馆自己的 `src/character-card-parser.js`** → 比对角色名（`scripts/verify-with-sillytavern.sh`，CI 的 `interop` job 每次 push 都跑）。格式是别人的，只有别人的实现能当裁判。

## 4. 提示词引擎（最值钱的一层）

### 4.1 段落顺序

`src/prompt/assemble.ts` 拼出来的顺序是固定的，`stats.sections` 会把这一轮实际贡献了内容的段落如实报出来（前端可以直接当调试信息显示）：

```
定义块：
  main（默认主提示词，可覆盖）
  card_system_prompt（卡的 system_prompt）
  world_info_before / world_info_after   ← 世界书命中，按 order 排
  角色定义（description / personality / scenario …）
消息序列：
  world_info_before_examples → examples（mes_example）
  world_info_after_examples
  world_info_before_history
  memory（前情摘要，system 块，仅在历史之前）
  history（含 world_info_at_depth 按深度插入）
  world_info_after_history
  post_history_instructions（始终紧贴本轮用户消息之前）
  本轮用户消息
```

### 4.2 历史裁剪：三级优先

`selectHistory()`（`src/prompt/assemble.ts`）从末尾往前装，装不下就停。顺序是**近期 > 开场白 > 角色顺序**：

1. **近期优先**：从最新往回填，直到预算或条数上限。
2. **开场白**：一般应该留下（它建立了场景）。如果加不进预算，就挤掉**最旧**的一条已保留轮次——但绝不动最新那条：你正在进行的对话比开场白重要。
3. **角色顺序**：裁剪落在回合中间时，窗口会以角色的发言开头，模型接着就会自问自答。所以窗口首部若是 assistant，就丢掉它（开场白例外，它是合法的开头）。

`stats.historyDroppedForRoleOrder` 单独计数，就是为了让"为什么少了两条"可查。

### 4.3 世界书

实现了：大小写/整词/正则匹配、扫描深度、四种次关键词逻辑、`constant`、`disable`、`delay`、`probability`（随机源可注入，所以能测）、`sticky` + `cooldown`、按 `order` 取舍的预算、三种递归开关、位置映射与 `atDepth`。

**刻意与酒馆不同的地方**（每一条都是权衡，不是偷懒）：

| 项 | 酒馆 | 这里 | 为什么 |
|---|---|---|---|
| 预算单位 | 上下文的百分比（默认 1500 = 15%） | 估算 token 绝对值 | 这里的"上下文"取决于调用方给哪个模型，用绝对值更可预测 |
| 整词边界 | `\b` | 只把拉丁字母/数字当词内字符（`src/prompt/worldinfo.ts:183`） | 中文没有空格，`\b` 在中文里永远匹配不上——酒馆的这个做法对中文世界书是失效的 |
| Author's Note | ANTop / ANBottom 专门注入 | 归并为"历史之前 / 之后" | 没有独立的 AN 概念，语义上就是插在历史边界 |
| `outlet` | 由前端指定的命名出口 | 归入 `after` | 没有前端可挂载的出口概念 |
| 群组、向量检索 | 有 | 未实现 | 见 §12 |

还有一个**同轮兄弟可见性**的坑：世界书词条激活后，它注入的内容不该让**同一轮递归**里的其他词条立刻匹配到（否则一轮之内会连锁引爆）。做法是把本轮新激活的文本只放进"下一轮递归"的匹配材料（`pendingHaystack`），而不是当前这轮的。

### 4.4 token 估算

`src/prompt/estimate.ts`：码点大于 `U+2E7F` 的字符（CJK、假名、谚文、全角标点等）按 1 token，其余按 4 字符 1 token，每条消息再加 4 token 框架开销。带音符的拉丁字母（`é` 之类）落在阈值以下、按窄字符算——对拉丁文字够用。

这是**估算**，因为精确计数需要目标模型自己的分词器，而每家都不同。它只用于一个目的——决定"这一段装不装得下"。所以 `PromptStats` 把估算值、历史占比、是否超预算都报出来，让调用方看到假设，而不是让调用方猜。

### 4.5 摘要记忆（M5）

长对话的处理方式是**滚动摘要**，不是向量召回：

- 未摘要的消息数达到阈值（默认 40）触发一次；
- 把「已有摘要 + 新的一段对话」交给模型**合并**成新摘要（不是重写，压过的信息不会丢）；
- 最近 `keepRecent` 条（默认 12）永远保持原文，摘要不追着当前对话跑；
- 摘要作为独立的 system 块插在历史之前；**被它覆盖的消息不再重复发送**；
- 所以这个块的大小是恒定的，不随对话长度膨胀（实测 60 轮后提示词约 355 token）。

**为什么先做摘要而不是向量**：调 embedding 要两周，而用户能感知的差别很小；摘要是确定性的、可测的、且立刻解决"开头丢了"这个最痛的问题。向量召回是 §12 里排第一的未做项。

**`ChatSession.send()` 本身不做摘要**，这是有意的：摘要是一次真实的模型调用，也就意味着要花钱。何时付这笔钱必须由调用方决定——服务端在轮次之后单独走一遍 authorize → settle，CLI 每轮之后直接跑。

## 5. 两套账：额度与积分

它们回答的是不同的问题，所以是两套账，不是一套：

| | 额度（M4） | 积分（M6） |
|---|---|---|
| 回答 | 「这个账号一天最多烧多少 token」 | 「这个账号还剩多少钱」 |
| 保护谁 | 运营者的账单 | 用户自己的余额 |
| 存储 | `usage_ledger` | `credit_ledger` |
| 拒绝 | 402（日/月/全局）+ 429（并发）+ 400（单次上限） | 402 `insufficient_credits` |

**共同的第一原则：只追加**。余额与用量永远由 `SUM` 算出来，绝不维护一个可能漂移的可变计数器。

### 5.1 预留，而不是事后统计

检查完额度就发请求，会让十个并发请求一起通过检查、然后一起超支。所以 `BillingService.authorize()` 在调用**之前**按最坏情况（提示词估算 + 请求的 max_tokens）把额度**预留**下来，`settle()` 用真实用量替换它。预留表在内存里——这是单进程假设，多实例部署要挪到 Redis（明确记录在案）。

### 5.2 幂等键

| 账本 | 唯一键 | 作用 |
|---|---|---|
| `usage_ledger` | `(user_id, request_id)`，部分唯一索引 | 同一个 requestId 重发不会重复计费 |
| `credit_ledger` | `(user_id, reason, reference)`，部分唯一索引 | 重试的轮次、重复的签到、重复的兑换只扣/发一次 |

这是 M2 那条「中断可重试且不重复扣费」的落点：requestId 命中缓存时连模型都不会再调一次。

### 5.3 不计费的失败

客户端断开或模型失败的那一轮**不写流水**——用户什么都没拿到，不该收费。但预留期间它确实占着额度，所以并发与熔断的保护不受影响。这是有意的取舍：宁可少收，不可错收。

### 5.4 积分是在调用之后扣的

成本只有模型回复之后才知道，所以扣费**不可能是前置条件**。做法是：请求前只查余额，为 0 直接 402，**模型根本不会被调用**；回复后按实际 token 数扣（向上取整）。扣费失败只记日志，不改变已经返回给用户的回复——真正的硬上限是额度，不是积分。

## 6. 市场

### 6.1 发布时快照

发布时把 `name` / `tags` / 描述长度**快照**进 `character_shares`。所以浏览列表**不读任何用户的目录**——这是市场页能快的前提，也是"发布"作为一个显式动作存在的原因（不是扫描出来的）。

代价：卡改了而没重新发布，市场的展示会过期。重新发布会刷新快照，但**保留首次 `published_at`**，否则改一次就跳到"最新"第一。

### 6.2 榜单按天聚合

`character_stats` 一行/角色/天。`day`/`week`/`month`/`all` 四种窗口都是对这张小表的范围扫描，而不是扫原始浏览事件——所以榜单的存储增长与"角色数 × 天数"同阶，与浏览量无关。

权重：`收藏 × 3 + 导入 × 2 + 浏览 × 1`。收藏是最强的意图信号，浏览最弱。

### 6.3 不刷分

- 看自己的发布不算浏览；
- 浏览/导入**未发布**的角色不计入统计（按 id 猜也拿不到）；
- 收藏是幂等的（重复 true 不会累加）；
- 导入自己的发布被拒。

### 6.4 导入是复制

导入 = 把对方的卡 PNG 复制进自己的库。卡里内嵌的世界书随 PNG 一起走，所以复制品能独立工作，不需要回头读发布者的目录；原主人那份不受影响。

## 7. 多用户、隔离与认证

- **隔离是文件系统边界**：每个用户一棵 `<dataRoot>/users/<userId>/`。所以"别人的角色"在同一个人库里**根本不存在**（实测 404），而不是靠查询条件过滤。这条比"记得加 where user_id"可靠得多。
- **会话**是不透明随机 token，库里只存 SHA-256。不用 JWT：登出必须真的能吊销，而且没有签名密钥需要轮换。
- **密码**用 scrypt，且**参数内嵌在哈希串里**（`scrypt$N$r$p$hash`），所以以后提高成本不会让老密码全部失效。
- **第一个注册的账号自动成为管理员**（否则没有任何途径拿到 admin）；之后可以关掉注册，但 bootstrap 仍然允许。
- **单用户模式**（`STORY_AUTH=off`）没有账号、额度、积分，直接用一个库——它只应监听回环，因为没有任何鉴权。

## 8. HTTP 层与流式

不用框架是刻意的：路由就几十行，而且**没有任何中间件能缓冲我们没让它缓冲的响应体**。

SSE 能不能用，取决于四条不变量，任何一条破了都会变成"模型卡住了"：

1. 响应头 `Cache-Control: no-cache, no-transform`；
2. `X-Accel-Buffering: no`（给 nginx 类反代）；
3. Caddy 的 `reverse_proxy` 必须 `flush_interval -1`（`deploy/Caddyfile`）；
4. **不能压缩 `text/event-stream`**——所以 Caddyfile 里压缩只匹配 JSON。

这四条都有 CI 断言守着（`deploy` job 里那两条），因为在真实链路上它们只在"字突然一起冒出来"时才会被发现。

其它约定：

- 公开路径只有 `GET /`、`GET /health`、三个认证端点；其余都要 Bearer token 或会话 cookie；
- `GET /` 说明这个服务是什么、有哪些接口（没有前端，所以根路径不能是裸 404），没有账号时顺带提示去注册；
- `/health` 在开启账号时**不返回库的绝对路径**——探针不需要知道服务器的文件系统布局；
- `POST .../messages` 带 `requestId` 时是幂等的：命中缓存直接返回上一次的回复，模型不会被再调一次。

## 9. 存储与迁移

用 Node 内置的 `node:sqlite`：既有真正的 SQL、事务、索引、唯一约束，又保持零依赖。换 PostgreSQL 是替换 `src/db/database.ts` 这一层的事，不是重写 API。

迁移是版本化语句列表，每个迁移在自己的事务里跑，`schema_migrations` 记录已应用到哪一版。当前是 **v2**。

**一个诚实的记录**：v2 里 `DROP TABLE` 重建了 `character_shares`。M4 建它时用 `character_id` 单独做主键，这是错的——两个用户都可能有 `linzhao`，它跨用户不可能唯一。发现时该表还没有任何数据、项目也从未部署过，所以直接重建（改成 `(user_id, character_id)` 复合主键，并补上市场需要的快照列）。写在这里是为了说明：**没部署过就不必背兼容包袱，但要在迁移里写清楚为什么可以这么干**。

连接打开时设了三条 pragma：`journal_mode = WAL`（读不阻塞写）、`foreign_keys = ON`（SQLite 默认是关的，而 schema 依赖它）、`busy_timeout = 5000`。

## 10. 部署形态

镜像 = `node:22-alpine` + `package.json` + `src/`。没有构建步骤，没有 node_modules（`deploy/Dockerfile` 里那条 `chmod -R a+rX` 是因为 `COPY` 会保留检出目录的权限位，而检出目录可能是 600）。

- 应用以 `PUID:PGID` 运行（非 root），**只读根文件系统**，只有 `/data`（绑定挂载）与 `/tmp`（tmpfs）可写；
- Caddy 终止 TLS 并自动续期，应用端口只绑回环，对外只有 80/443；
- 运行时状态全部在 `deploy/` 下：`data/`（SQLite + 每个用户的库）、`caddy/`（证书）、`backups/`、`.env`（模型 key）。代码与状态分离，所以 `git pull` 不会碰数据。

**备份的诚实说明**：备份是 tar 一份正在被写的目录，属于**崩溃一致**而非在线一致。SQLite 走 WAL，归档里包含 `-wal`/`-shm`，恢复后它会像断电重启那样正常回放或回滚。要一份"按构造就干净"的快照，就在备份前停栈（`deploy/README.md` 里写了）。归档同时包含 `.env`（模型 key）和数据库（密码哈希），因此**归档本身就是机密**，权限 600。

## 11. 测试策略

204 项测试（2 项需要真实酒馆目录，默认跳过），分层如下：

| 层 | 怎么测 | 例子 |
|---|---|---|
| 格式层 | 真实样本 + 交叉验证 | V1/V2/V3 归一化、CRC-32 与真实 PNG、导出的卡被**酒馆的解析器**读回 |
| 提示词 | 纯函数快照 + 断言 | 段落顺序、裁剪三级优先、世界书各语义、摘要注入位置 |
| 会话 | 内存 + 落盘对比 | 20 轮不串味、中断不留半截、重新生成不追加 |
| 服务层 | 真 HTTP + 真 SQLite + mock 模型 | 401/402/403、两账号隔离、SSE 逐帧、幂等重发只调一次模型 |
| 部署件 | CI 里真跑 | 构建镜像、真跑 backup.sh 并校验归档、Caddyfile 的 SSE 两条断言 |

**mock 模型会回显它收到的提示词**，这是不接真实模型也能断言提示词行为的关键（`test/helpers/mock-model.ts`）。它还会说 SSE 里那些难缠的形态：CRLF、心跳注释、非 JSON 行。

几条回归测试的来历值得单独说，因为它们都是真 bug 换来的（不是凭空写的）：

- `tar -tzf | grep -q` 在 `pipefail` 下被 SIGPIPE 反转，把**有效备份判成无效**——测试里专门造 2000 个文件把归档列表撑成流式；
- `assert.throws` 返回 undefined，于是"断言抛错"的测试其实什么都没断言；
- 中文/空格会话名走 URL 要按段解码，否则整条路由不可用；
- `deploy/*.sh` 少了可执行位——`git` 只记录可执行位，clone 出来就不能执行，而 systemd 的 `ExecStart` 直接调用它；
- `tar --create --gzip` 之后不能再 `--append`，备份**必然失败**而静态检查看不见。

**关于 CI**：GitHub Actions 目前被账号的账单问题锁着（所有 job 都 `startup_failure`，annotation 原话是 account is locked due to a billing issue）。所以两个仓库的 workflow 都被逐条在本地复现过一遍（含 `shellcheck` 与真跑备份脚本）。这不是替代品——**能自动跑的前提是账号恢复正常**。

## 13. 接手者从哪开始

- **要做前端**：`GET /` 返回的端点表 + README 的接口清单就是全部契约。第一步接 `POST /auth/register|login`（拿 token）、`GET /characters`（列表）、`POST /chats/:c/:n/messages`（`stream: true` 走 SSE，注意 §8 的四条不变量）。
- **要上规模**：先换 PostgreSQL（一个文件），再把 `BillingService` 的预留挪到 Redis。这两件事都不会碰格式层与提示词层。
- **要更像酒馆**：照 §4.3 的偏离表逐条补齐，从 Author's Note 和 `outlet` 开始（它们只影响插入位置，风险最低）。
- **要记住的一条**：格式层与提示词层是这个项目的资产，其余都是可替换的外壳。改动优先选外壳。
